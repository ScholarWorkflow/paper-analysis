## 1. 有效需求和边界

目标：关键词、目录、末尾页只是优先阅读提示；已经在同一 PDF 中发现并确认的真实未来工作原文，不能因没有进入候选表而无法保存。支持同页连续一至两句；相邻两页连续引文保留有限支持，作为次要场景，不因此新建跨页格式、改下游消费方或扩展解析框架。保持逐字可回溯、起始物理页码、PDF 指纹、文字质量门禁、稳定 ID、现有保存的全文分析与 facts 消费约定。

2026-10-23 用户明确的业务选择：

- **由模型决定语义**：使用现有论文分析模型已读的上下文判断是否为作者明确提出的未来工作，选择意思完整、保留前提条件和限制的原话；不得靠关键词或机械分句截取来决定语义，程序不得代替模型裁剪引文。
- **程序负责原文核验**：模型给出引文后，确定性程序只验证同一 PDF 的连续原文、必要的行末断词、质量、页码和指纹；找不到准确原文就拒绝保存，不能通过模糊匹配放行。
- **重复文本取首次**：引文在全文多处准确出现且原分析未明确指定页码时，按物理页码、页内偏移从小到大采用第一次有效匹配；不要求额外向用户或模型询问位置。显式提供的起始页码仍必须严格匹配。
- **少用模型上下文**：已完成的全文阅读与分析结果直接用于选句、翻译和组装；后续校验读取本地文件，不把整篇论文第二次交给模型，也不启动额外全文分析单元。独立 `gap-only` 只按需读取尚未检查的局部原文。

用户所述案例为 22 页 PDF 的第 18 页未入候选，同页两句被拆开，跨页句受到页眉/页码干扰。原 PDF 未提供：此为需求输入，不声称已复现；现有测试计划使用同机制合成 PDF。

非目标：扩充词典或末尾页数来回避根因；新增模型流水线、语义匹配/向量检索、模糊放行、通用 PDF 阅读顺序重建或来源认证；改动 Zotero/Contact、Nix 安装器、全文分析业务内容；批量重写既有 sidecar、重跑正常旧分析、让可读页因引用不匹配而重新 OCR。

## 3. 方案与接口

### 3.1 prepared 页级证据

`prepare.json` 保留现有字段并新增 `source_pages`：每页保存 1-based page、原始 text、可用于审计的页边缘文字排除区间；复用现有 page_quality 和 pdf_sha256，不建立第二套身份系统。新数据是临时准备产物，不是正式 sidecar schema 迁移。

页级文字来自现有 PyMuPDF 提取。必要的行位置来自同页文本布局信息，并映射回原始字符串位置；无法可靠映射的行不排除。顶部/底部各 8% 和跨页重复仅是噪声候选提示，不能直接授权删除。允许排除的必须是提取顺序最外侧连续页眉/页脚区间：独立文本块，几何上与正文块至少隔开一个该边缘块行高，且为独立纯数字页码或至少两页相同边缘区重复的完整相同行文本。出现正文交织、无法证明独立块/间隔、可能是正文或非最外侧区间时不排除，跨页定位失败也不放宽条件。排除区间保留原文和位置，不根据匹配能否成功反推页眉。此有限版面处理只用于跨页连接，不能删除同页句间文字。

候选文件/Markdown 和 selection 保留，语义明确降为提示。全页原文不会全部打印到 stdout；现有 prepare 短摘要保持。

模型可从已保存的 `source_pages` 定位真实引文；候选只指示先看哪里，不再形成可保存引文的白名单。已在本次模型上下文中的全文不再次全部发送给模型。

### 3.2 模型选句与确定性原文定位

**语义判断归现有模型，原文真实性归 `future_work.py`。** 保存的 PDF `full` 模式利用现有三路分析中负责论文内容的结果来判断作者是否明确承诺未来工作，并选择含完整语义条件的一至两句原话，同时给出翻译和章节出处。不新增第四个分析单元、第二遍全文模型阅读或独立的“句子语义判定”模型。若两句以内无法保留必要条件，模型应舍弃该条并说明，不能截去条件凑成候选。机器分句只能用于候选阅读提示或拒绝显然越界的长度，绝不替模型删字、补字或判定语义。

同一个 helper 内的原文定位方法供 `validate`、`finalize`、`upgrade-full-sidecar` 共用。比较允许现有 NFKC 和空白归一化；仅原文真实行末/页末连字符与后续字母相接时生成去断词的比较视图，并保留比较位置到原文字段的映射。普通行内 `- ` 不得删除；不做模糊匹配、同义词替换或为匹配而省去中间文字。

有效引用须连续落在一个可信页面，或两个相邻物理页的接缝处；跨页两端必须均有正文贡献，只能排除 §3.1 有版面依据的外侧噪声。不能跳过中间正文、非相邻页、标点或错误页面。程序按模型选择的完整引文验证，不机械拆成另一个意思不完整的新引用；超过现有长度限制或无法核验时明确失败。

位置规则如下：
- `items.json` 显式给出 `page`：仅允许从该起始页准确匹配；页码错误即拒绝，不改查其他页。
- `full` 已保存 Markdown 的旧格式没有明确物理页码：按 `source_pages` 的物理页码升序和原始字符偏移升序寻找第一处质量合格、连续准确的完整引文；多处出现直接使用首次位置，不报歧义、不要求新字段。跨页时 `page` 仍是起始页。
- 相同位置的断词比较可能对应多个可用候选时，按已保留的候选稳定顺序选第一条经原文核验的候选规范文本；不得根据关键词排名、模型偏好或字典覆盖顺序任意选末条。对于旧单候选的有效引用，保留它原有的规范 quote 和 ID。
- 出处的页码由准确定位结果生成：单页输出起始页；跨页将实际相邻页范围写入既有 `source` 自由文本（例如 `Conclusion (pp.18–19)`）。模型只提供章节/段落名称；若其附带的页码与定位不符，以实际定位页码为准，不保留冲突范围。正式 item 仍只有 `id/quote/translation_zh/source/page`，不新增必须字段。

**规范引文与 ID**：先证明模型提供的是有效连续原文；能对应通过同样原文核验的旧单候选时，沿用该候选原有的规范 quote 和 SHA256 ID，包括真实行末断词的不同展示；否则使用输入引文按既有 NFKC/空白规则生成规范 quote 与 ID。不得用旧 `match_quote` 无条件删掉 `- ` 的宽松行为认定候选等价。同一份正式 sidecar 内仍不允许重复 ID；不批量重写历史记录。

错误指向条目序号与不匹配原因。原文核验失败仅表示这条引用尚不能保存，不得推断整篇论文没有作者明确提出的未来工作。

### 3.3 调用与兼容

- 保留原 `--candidates` 和仅含 `candidates` 列表的旧输入路径，仍执行旧式单候选精确核验；旧文件不能凭空获得全页原文能力，也不静默重建。
- 新 `prepare.json` 含 `source_pages` 时，`validate/finalize/upgrade` 使用上述统一连续定位。新流程由 agent 传入 `prepare.json`，而旧 `candidates.json` 接口继续可用；升级不再依赖同目录下的兄弟 `candidates.json`。
- 使用新 prepared 的 `finalize` 在收到 `--pdf-sha256` 时必须验证它与 `prepare.pdf_sha256` 一致；未传时直接采用 prepared 的指纹。禁止将不同 PDF 的指纹与页原文混合；旧候选路径维持原参数行为。
- `gap-only` 先给现有模型看短候选提示；已知用户指定页、章节或候选不足时，仅将需要的尚未读过的 `source_pages` 局部原文交给**同一个现有分析过程**判断与选句，避免再次发送已有全文。未检查的页面不能据此宣称“整篇无未来工作”；需要更多原文但无合格页文本或 OCR 授权时报告未完成。不得另起第二轮全篇分析。
- 保留旧 sidecar 的 `schema=1`、`extractor_version=future-work-v1`、规范 quote/ID 和 facts 连接。仅改本次新生成的临时 prepared 与相应分析结果，不扫描、迁移或覆盖其他历史 sidecar。

### 3.4 质量和 OCR

全页 source_pages 中 untrusted/empty 文字不可直接变成已验证证据。prepare 的既有 selected required OCR 列表保持，不自动要求所有坏页 OCR。实际引用额外坏页时给出具体页码，先复用同次 full OCR 或已经由现有 pdf_runtime 验证同 PDF 的缓存；只在确实缺页且已有授权时走原 OCR 路径。

merge-ocr 除既有 required 页外，允许合并 page_quality 为 untrusted/empty 的额外实际引用页。保持现有 required 页完整性要求；已解决后可再次合并额外坏页。同步替换这些 source_pages 的文字并标记 OCR 已解决，同时按原 selection 刷新候选，不修改其他页。不得把好页当作匹配失败的 OCR 修复目标。使用现有 fingerprint 校验入口，不新建 cache 格式或认证系统。

### 3.5 保存顺序与模型输入成本

本地 PDF 的 `full` 流程必须沿用现有 agent 所要求的真实顺序：

1. **提取一次**：对当前 PDF 执行 `prepare`，完成全页质量分级；按已有授权复用同次全文 OCR、已验证缓存与必要的候选页 OCR，产生当前指纹绑定的 `prepare.json`。
2. **现有模型阅读一次**：复用既有三路论文分析，不新增分析叶子或重复全文提示；负责论文内容的模型在已有上下文内选完整 future-work 原话、翻译和出处。协调器复用三个结果组装 Markdown 与 `facts-draft.json`，不为引文校验重新阅读全文。
3. **先写分析 Markdown**：按原 `save` 流程把组装好的分析文本写到最终 `analysis.md` 路径并确认文件存在。这是下一步 `upgrade-full-sidecar` 的现有前提，此时不得宣称三文件完成。
4. **本地校验后生成 future-work sidecar**：`upgrade-full-sidecar` 只读取已写分析文件及同一份 `prepare.json`，逐条准确定位；所有条目通过后才修补 Markdown 的专用 future-work 小节，并写 `analysis.md.future_work.json`。失败时停止，不用模型重新阅读全文，不手工伪造 sidecar；初始 Markdown 即使已存在也不算成功。
5. **生成 facts sidecar**：仅在 future-work sidecar 有效后，以之前已产生的 `facts-draft.json` 调用原 `facts.py finalize`，检查分析身份、证据级别和 PDF 指纹一致，然后写 `analysis.md.facts.json`。
6. **报告结果**：只有分析 Markdown 与两个 sidecar 全部存在、两个 sidecar 状态有效，才报告完整成功。单文件原子写行为保留，不宣称跨文件事务。

独立 `gap-only` 不走三路全文分析：在现有模型流程中选句与翻译，本地校验通过后才对既有分析文件执行定点修补并生成 future-work sidecar。所有后置程序只读取本地准备产物和已写文本，不再次向模型发送论文全文；真正需要模型纠正的单条引文只提供必要的局部原文与失败原因，不自动重复整篇分析。

## 5. 保持行为、影响和风险

- **保持**：作者明说的未来工作才可入选；模型负责语义判断；单条原文至多两句；已有效单候选的规范 quote/ID；`schema=1`、`future-work-v1`、`id/quote/translation_zh/source/page`；分析 Markdown→future-work sidecar→facts sidecar 的保存顺序；分析/facts 同源指纹；现有 APM、运行环境、OCR 权限与缓存。
- **用户本轮确认的行为调整**：非候选页的真实原话允许校验与保存；模型按上下文选取意思完整的原文，代码不机械截句；未明确标页的重复引用选首次真实位置；有相邻两页引文时保留有限准确核验；后置校验仅消费本地文件，不第二次整篇模型阅读。
- **禁止副作用**：编造作者待做事项、漏掉条件而改变引文意思、模糊匹配或跳句、自动把坏 OCR 当可信证据、为“找得到”擅改指纹/页码、重复全文模型分析、批量改旧 sidecar、扩展 Contact/Nix/全业务回归、更改用户全局配置。
- **有限版面限制**：页眉、页脚只在 §3.1 的独立块与位置条件成立时退出跨页比较视图；多栏正文顺序无法可靠确认、超出两页或有无法解释的中间正文时明确定位失败，不自行放宽或增加版面重建引擎。跨页不是主任务的扩大许可。
- **状态与失败**：新 `prepared` 是临时证据文件，复用现有 PDF/cache 指纹链，不声称可认证人为篡改的 prepared；原有单文件原子写保留，不承诺两个 sidecar 与 Markdown 跨文件事务。全文初始 Markdown 可能先写入，但其后的校验失败必须返回失败且不得报告三文件完成；并行论文使用独立临时目录。
- **替代方案与取舍**：扩大关键词或候选页仍会漏掉无提示原话；让程序机械拆句会丢掉条件；把全文再传给模型复查会增加词元消耗；让下游修正来源会错置 owner。本方案保留现有分析模型的语义判断，只把证据定位与保存失败交给本 helper，代价是复杂 PDF 或未读取的 `gap-only` 页可能需要额外局部原文，无法可靠定位就明确未完成。
